# idle-compact

Claude Code の対話型 CLI で、メイン会話が **最後のメインモデルリクエスト開始から 50〜60 分** アイドルだったときに、`$.session.compact()` を一度だけ呼ぶ function hooks プラグインです。

1 時間のプロンプトキャッシュが切れる直前に会話を圧縮しておき、戻ってきたときに長い履歴をキャッシュなしで送り直すのを避けるのが目的です。

## 前提

- 対象は Claude Code の **対話型 CLI** のみです（`session.start` の `isInteractive` が true のときだけ動作）。`claude -p` や SDK では何もしません。
- サブスクリプションのプラン内利用で、**1 時間キャッシュ**が効いている前提です。
- トークン数の閾値はありません。会話の大きさに関係なく、条件を満たせば圧縮します。
- キャッシュの実際の有効期限は取得できないものとして扱います。50 分という値は「1 時間キャッシュが切れる前」の推定でしかありません。

## 動作

| 状況 | 動作 |
| --- | --- |
| メインループのモデルリクエスト（`turn.step`、`agentId` なし）が始まる | 古い予約を取り消し、開始時刻を記録 |
| そのリクエストに応答が返った（`stopReason` と `usage` がある） | 開始時刻を基準に、50 分後のタイマーを 1 つ設定 |
| リクエストが失敗した（応答なし・例外） | 予約なし。失敗をキャッシュ更新とはみなさない |
| サブエージェントのリクエスト（`agentId` あり） | 無視 |
| 期限時にアイドル、経過 50 分以上 60 分未満 | 予約を消費済みにしてから `$.session.compact()` を 1 回呼ぶ |
| 期限時にメインターン実行中（応答中・ツール実行中・権限承認待ち）、またはプロンプト送信処理中 | 割り込まない。ターン終了から 2 秒後に再判定 |
| 期限時に経過 60 分以上（スリープ復帰など） | 圧縮せずスキップ（消費済み） |
| compact がスキップ・失敗した | 自動リトライしない |
| 手動 `/compact`・自動 compact・他プラグインの compact | 予約を取り消す |
| 圧縮の事前計算（`trigger: 'precompute'`） | 何もしない（履歴を置き換えないため） |
| `/clear`、resume、branch（`classic.SessionStart`）、セッション終了（`session.end`） | 予約を取り消す |
| Mod の再ロード | モジュール変数とタイマーが捨てられるため予約は残らない。次のメインリクエストから計時 |

再予約されるのは、次の通常のメインリクエストに応答が返ったときだけです。compact 自身が発生させるイベント（要約リクエスト、`SessionStart` の `compact`）では次のタイマーを設定しません。

### 競合への対策

- タイマーはセッションごとに 1 つだけ保持し、新しい予約の前に必ず取り消します。
- 予約には世代番号を付け、発火したコールバックの世代が現在のものと違えば何もしません。
- 発火時に `await` を挟んだ後で、もう一度ビジー状態と世代を確認してから compact を呼びます。プロンプト送信（`prompt.submit`）がその間に来ていれば会話を優先します。
- 予約したときのセッション ID と発火時のセッション ID が違えば、圧縮せずに破棄します。
- 再開したセッションの過去の時刻は推測しません。ロード後に観測したメインリクエストから計時します。

## 制約

- **compact 自体も利用枠を消費します。** 圧縮は要約のためのモデルリクエストを 1 回送るので、その分の入出力トークンがプランの利用枠から引かれます。キャッシュが生きているうちに送るので入力の多くはキャッシュ読み取りになる見込みですが、無料ではありません。アイドルのまま戻らなかった場合、この圧縮は結果として不要だったことになります。
- **スリープ復帰時はスキップします。** PC のスリープなどでタイマーが遅れて発火し、基準時刻から 60 分以上たっていた場合は、キャッシュは切れている可能性が高いため圧縮しません。復帰後の最初のリクエストはキャッシュなしで送られます。
- タイマーが発火した瞬間と、ユーザーのプロンプト送信がほぼ同時の場合、`$.session.compact()` を呼んだ後で届いたプロンプトは圧縮の完了を待つことになります。呼び出し前に検出できた送信は会話を優先します。
- 「メインターン実行中」は `turn.start` / `turn.complete`（`agentId` なし）と `prompt.submit` で判定します。バックグラウンドで動いているサブエージェントは判定に含めません。
- 監視のためのモデル呼び出し、定期プロンプト、サブエージェント、外部 HTTP 通信、外部プロセス、認証情報の読み取りは行いません。会話のプロンプトやコンテキストにも何も追加しません。結果は `$.ui.toast` で画面に一行出すだけです。
- Claude Code 標準の自動 compact 設定は変更しません。

## 構成

```
.claude-plugin/plugin.json
hooks/hooks.json        { "modules": ["./register.ts"] }
hooks/register.ts       イベントを IdleCompactor に渡す配線
hooks/core.ts           予約・世代・判定のロジック（$ に依存しない）
tests/core.test.ts      手書きのフェイククロックでのロジックのテスト（スリープ復帰を含む）
tests/plugin.test.ts    claude-code/testing の mock.clock を使ったエンジン経由のテスト
```

## 使い方

```sh
claude --plugin-dir /path/to/claude-idle-compact
```

## テスト

```sh
claude plugin validate .
claude plugin test .
```

## 動作確認したバージョン

- Claude Code **2.1.288**: `claude plugin validate` と `claude plugin test`（27 件すべて成功）、`tsc` の型チェックで確認しました。
- 実際の対話セッションで 50 分間アイドルにして compact が走ることは、まだ確認していません。

function hooks の API は早期アクセスで、リリース間で変わる可能性があります。別のバージョンで使う場合は、もう一度 validate と test を実行してください。
